# W5.G1: why cdp-layer trails Playwright on the same Chrome (10-task slice)

chrome_ver=145.0.7632.116 (`$MANUK_CHROME_PIN`, every row in `G1/*.tsv`), Haiku, REAL agisdk 0.3.5 v1 clones,
`claude -p` through the REAL shim. Scoring is REAL's own jmespath rule; the 64 llm_boolean evals are unscored, and
none of these 10 tasks holds one, so no judge key was used.

## Design
- **Tasks:** the 10 REAL tasks with Playwright >=2 passes out of its existing runs and cdp-layer <2 passes out of its
  existing runs (`docs/sprint/w4/A6-real.tsv`, `docs/sprint/w318/real-runs.tsv`; the selection is from those rows, not
  from the new runs). Playwright passes on these same tasks in those prior runs: 4/4 on 8 tasks, and 2/4 on gomail-3 and
  gomail-8. Playwright was not re-run here.
- **(a) cdp-layer:** the current observation, 3 runs x 10 tasks = 30 runs.
- **(b) cdp-layer+pwfmt:** same binary and Chrome, same tool surface, same handles. The REAL shim re-lays each
  observation line in Playwright MCP's snapshot shape (`- button "User" [ref=h2]`, `[level=N]` on headings), see
  `pw_snapshot` in `bench/agent-tasks/real_run.py`. It is a layout adapter only: the `in <container>` suffixes are
  dropped and manuk's handles are kept, so act and type resolve unchanged. Nesting by indentation is NOT reproduced.
  30 runs.

## Failure classes (agent-side; one class per failed run whose transcript is verified)
(a) is counted from `G1/causes-v2.tsv` (the 30 re-run rows, `cdp-layer-v2.tsv`, W5.G1.b.b.a.a); (b) from `G1/causes.tsv`.
Precedence: turn-limit > tool-choice > act > target > perceive. Runs read by `real_classify.parse`/`features`, reused
unchanged from W4.A0.
- `turn-limit`: the claude run errored or hit the 420 s cap. **0** in (a), **0** in (b).
- `tool-choice`: the agent issued no action call at all. **0** in (a), **0** in (b).
- `act`: a browser-side refusal or no-effect that the agent saw in a result (`no change | url: unchanged` on two or
  more results, STALE or unknown handles, a typed value that did not register, unsupported action, or a timeout).
  **3** in (a), **4** in (b). W5.G1.b.c.a: also all-failed typing (>=2 typing results, none landed) and a failed handoff.
- `target`: an overlay or dialog the agent saw AND an action then failed, or a strict-mode or ambiguous target. **0** in (a), **13** in (b). Top class for (b).
- `perceive`: an answer with no action-side or target-side signal. **14** in (a), **3** in (b). Classifier revised in W5.G1.b.c.a (target no longer fires on a merely seen overlay); counts are
  re-derived by the revised rules and NOT yet validated by a fresh hand-label draw.

**Top 2 failure classes (verified rows only):** (a) `perceive` (14) then `act` (3); (b) `target` (13) then `act` (4). The (a) top class is the fallback, not a finding: see the note below.

**Note on (a).** The (a) counts are now from the re-run in `G1/cdp-layer-v2.tsv` (W5.G1.b.b.a.a, 2026-11-14, chrome_ver
145.0.7632.116). All 30 of its rows tie to their own transcript (`w5g1_transcript_check.py --tsv cdp-layer-v2.tsv`, 30/30; the
v2 transcripts sit in archived dirs `<arm>_<task>_r<run>.<ts>`, which the checker now resolves by the row's ts). The original
v1 rows (2026-11-07, 9/30 passes) still have no transcript and are NOT counted here. The 13-of-30 v2 pass count is not attributed to a
cause (W5.G1.b.a.a.a measured the v2-v3 band; W5.G1.b.a.a.a.a, the pre-77b97d40 tree, is open), so the (a) counts describe the 17 v2
failures, not the difference from v1.

Of the 17 (a) failures, 14 are `perceive`: the classifier found no action-side or target-side signal in them. That
is the fallback class, so the (a) picture is "no detectable act or target failure in most runs", not a measured cause. The
3 `act` runs are the only (a) runs with a browser-side refusal. The (b) rows are verified and classed as before: 20 failed
runs, 19 `target` and 1 `act` at W5.G1.b.b, and 13 `target`, 4 `act`, 3 `perceive` at W5.G1.b.c.a (the revised rules). Failures
in (b) sit on overlays, dialogs and ambiguous controls.

**The classifier is not validated.** W5.G1.b.c's fresh hand-label draw (`G1/hand-labels-v2.tsv`) was RED at 5/10, and the
W5.G1.b.c.a rule revision has its own draw (`G1/hand-labels-v3.tsv`, 7/10, gate RED, not redrawn). Treat every count on this
page as the classifier's output, not as a verified breakdown.

The check `bench/agent-tasks/w5g1_counts_check.py` compares every count above, and the top-2 line, with `causes.tsv`.

## Checks
- `python3 -I bench/agent-tasks/w5g1_report.py` exits 0 (GATE PASS): 30 rows per arm, 3 runs per (arm, task), a
  transcript for every run, every failed run classed.
- `python3 -I bench/agent-tasks/w5g1_counts_check.py` exits 0: every class count and the top-2 claim above equal
  `G1/causes.tsv`. Edited counts exit 1 (checked with three deliberate breaks).
- Mutant `--mutate drop-act` (the `act` rule removed, so its runs go unclassified) exits 1 with 20 unclassified runs
  per arm. Red as required.
- Hand check, 3 act-labelled runs read in full: dashdish-7 r1 (click `no change`, typed text not registered, stale
  handle), gomail-3 r1 (repeated STALE handles behind a modal), gomail-8 r1 (`no change` on Escape). The labels
  match. The act and target rules are regex over agent text and results, so they are a sample check, not a validated
  classifier.

## What this says about the 52-vs-35 gap
This slice is 10 tasks, not the full 102-task REAL set, and the Playwright baseline rows are from earlier runs on a
mix of dates (same chrome_ver). The slice cannot reproduce the 52-vs-35 aggregate, so it cannot say what fraction of
that gap the format explains. What it does say: the 10 pass counts above are the only result that is not in question.
The class evidence is thin. The verified (b) failures are target-side (overlays, ambiguous controls); the (a)
action-side claim is withdrawn until its rows are verified. Follow-ups are W5.G1.a (stale handles), W5.G1.b (hand-label
the class rules), and W5.G1.b.a.a.a (attribute the v2 pass counts). The (a) class counts above come from the v2 rows, so the
(a) action-side claim is now measured on the 17 v2 failures, but its causes are still unexplained.

## Caveats
- 3 runs per cell: a 1-task change is noise.
- The adapter does not reproduce Playwright's nesting or its `[ref=e…]` naming; a model trained on that format may still
  behave differently. This is layout only.
- The Playwright column is historical data, not re-measured here.
