## Method

- Each failed run (`pass = 0`) gets exactly one label. The first cause in the precedence list below that fires wins. The precedence is in `cause()` in the classifier.
- Signals come from the tool results (regex on the page-state text the tools return) and from the assistant text (regex on what the agent says about its own failure).
- Precedence: `typed_not_registered` > `dialog_modal` > `handle_lost` > `act_before_reacted` > `ambiguous_target` > `key_hover_enter_gap` > `timeout_cap` > `wrong_answer` > `no_signal`.
- `wrong_answer` is a catch-all: the run ended with a final answer and no layer signal fired. It is not validated, and on the Playwright arm it absorbs most failures.

## Caveats the table hides

- **Playwright is not comparable on the tool surface.** Its failed runs include `Bash` (160 calls) and `Read` (145 calls) on the same task set, and snapshot results that exceed the maximum allowed size (37 + 12 errors). Its `wrong_answer` bucket (48) therefore mixes real answers with runs that never saw the page.
- **The `key_hover_enter_gap` count is inflated by one-shot probes.** Most runs try `focus` or `hover` once, get "not supported by this backend", and move on. The cause only ranks after the layer defects for that reason.
- **`typed_not_registered` is partly a regex artifact.** The "stays disabled" phrase (25 hits in manuk's text) is mostly the networkin Post button, which is a real symptom. The phrases "greyed out" and "didn't take" are sometimes about a date picker or a year selector, not a typed field.
- **Dialog and modal is the signal to trust most, but recall is not complete.** In sample 2, the classifier's `dialog_modal` label was right on 3 of the 5 runs that a hand label called dialog or modal (rows 3, 7 and 9); it missed rows 1 and 2, where the agent described a popover that would not open or take clicks.

## What this means for the wave

- Typed text failing to register and overlays blocking the target are the two largest causes for manuk and for the rollback arm. Both are candidates for the A1 and A3 nodes, but A0 does not yet establish them with a validated classifier.
- For cdp-layer, `handle_lost` is the largest cause. That is closer to the W3.12 / A4 handle work.

## Primary-cause rubric for multi-cause runs (W4.A0.a.a.a.a.a.a)

Written before the new second-pass sample is drawn. A run gets the label of the first rule that fits, applied to the final answer (its own account of what stopped it) plus the last three tool results.

1. **Root over symptom.** If the final answer names an overlay/modal that the agent could not dismiss as the reason the form or target would not work, the label is `dialog_modal`, even when the visible tool errors are STALE handles or unresponsive clicks (those are downstream of the overlay).
2. **Layer cause named beats residual.** If the final answer says a specific control did not respond (a click "did nothing", the value would not register), that is the cause (`click_no_effect`, `typed_not_registered`) even if the agent also made its own mistake. `wrong_answer` is used only when no control or layer failure is named.
3. **Unresponsive vs unreachable.** `widget_unreachable` only when a tool result says there is no clickable area, the control is offscreen, inert or occluded. A control that took the click with "no change" or "did not respond" is `click_no_effect`.
4. **Left-alone overlays do not count.** An overlay the agent chose not to touch because dismissing it would undo the task (e.g. a Cancel dialog) is not a blocker; use the next rule that fits.
5. **`handle_lost`** applies only if STALE results are the final answer's own stated blocker and no overlay is cited (rule 1).
6. Ties after rules 1-5: `dialog_modal` > `typed_not_registered` > `click_no_effect` > `widget_unreachable` > `handle_lost` > `app_error` > `stopped_early` > `wrong_answer`.

New causes:
- `payment_rejected`: the final answer says the site rejected the card (expiry, declined, invalid card number).
- `task_data_missing`: the final answer says the task did not supply something required to finish (e.g. CVV, a password, a value) and the agent stopped for that reason.

## Playwright rubric rules 7-8 (W4.A0.b.a)

Written BEFORE any row is relabelled and BEFORE the new sample is drawn. They come from the two gaps named in the W4.A0.b second-pass misses, not from a label pass.

- Rule 7 `declined_action`: the final answer says the agent chose not to perform the final action (send, place order, submit, book) — it drafted or prepared it, or asked for confirmation — and names no tool or site failure. Applies only when the page state otherwise worked. It takes precedence over residual `wrong_answer` and over `stopped_early` when the stated reason is a decision, not a blocker; `stopped_early` stays for runs that stop because of an explicit obstacle or running out of steps.
- Rule 8 `state_not_persisted`: the agent submitted a form/action, the site gave no error (redirect or success-looking response), and the final answer or last tool results show the result is not visible afterward (post missing from the list, item not in the cart). Takes precedence over residual `wrong_answer` and over `app_error` when no error message was shown.

Order for playwright becomes: rule 1 > `payment_rejected` > `task_data_missing` > `never_reached_page` > `tool_surface_gap` > rule 8 `state_not_persisted` > rule 7 `declined_action` > rules 2-6 > `wrong_answer`.
