## Pre-registered rule (fixed before any X1 row existed)

Written before the mutant job ran. Not to be edited after results.

- Task passes an arm if >= 2 of its 3 runs pass (task_pass_2of3).
- Per-task band: the unmutated passing-run count for that task, +/- 1 run. A task **moves** if the mutant's passing-run
  count is 2 or more runs away from the unmutated count.
- Verdict:
  - **moved >= 2, all upward** (mutant better): the overlay guards are blocking passes. Keep W6.C1 (overlay handling)
    prioritised.
  - **moved <= 1** (passes stay inside the per-task band): overlays are real blockers that the guards do not cause.
    Deprioritise W6.C1. This is the node's falsifier as written in GRAPH.tsv.
  - Otherwise: mixed, not decided by this rule; report it and escalate rather than pick a side.

Implementation: `bench/agent-tasks/w6x1_tally.py` (refuses on a non-primary judge, a wrong chrome_ver, or a missing
(task, run) key; `--self-test` shows the verdict and the refusals can go red; `--mutate N` flips N mutant runs).

### Caveat on power

Pass counts are very low in both arms (unmutated 3/45, mutant 2/45). A task can only move with a 2-run difference, so
this test cannot detect a modest overlay effect. The result says the removed guards do not turn these tasks into
passes. It does not show that the guards are irrelevant to other tasks, and it says nothing about the 0-pass tasks
beyond that. The rule was applied as written and not re-tuned.

### Self-test and gate sensitivity

`INSIDE_BAND`, and wrong chrome_ver, a missing (task, run) key, and a non-primary judge each refuse.
