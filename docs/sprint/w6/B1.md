# W6.B1 Sonnet driver arm: does the driving model change the arm ordering on the REAL-fast subset?

Written before any `claude-sonnet-5-5` row exists. Tool: `bench/agent-tasks/b1_driver.py` (self-test green before this file was committed).
Queue spec: `bench-queue/specs/w6b1-driver.json` (18 steps: 2 drivers x 3 arms x 3 runs, one HEAD, one pinned Chrome, one primary judge).
Owner decision (2026-11-19): run the REAL-fast subset with claude-sonnet-5-5 as the driving model, through the `claude` CLI, no API key.

## Design

- Subset: the 17 tasks of `bench/agent-tasks/fast_subset.py` (W6.F1: 12 GAP + 5 AHEAD; dialog_modal tasks excluded).
- Arms: `manuk`, `cdp-layer`, `playwright`. Each arm is run x3 under each driver:
  - `haiku`: the default driver, `--model haiku` (the value every earlier row carries).
  - `sonnet`: `MANUK_DRIVER_MODEL=claude-sonnet-5-5`, the only change between the two arms of a pair.
- Both drivers are run at the same HEAD. Earlier haiku tables (RG.2.B, W6.B0, W5.B1) were measured at other commits, and
  the W5.B1 cdp-layer/playwright tables were judged by the fallback judge, so they are NOT used as the default-driver
  reference. The haiku rows are regenerated in the same job.
- chrome_ver = `$MANUK_CHROME_PIN` (145.0.7632.116) on every row. Primary judge `openai/gpt-oss-120b` on every row.
- Refusals (exit 2): wrong chrome_ver, a `model` column that is not the expected driver, a non-primary judge, a missing (task, run) key.

## Pre-registered rule (fixed here, before sampling)

- M(arm, driver) = mean over the 3 runs of the per-run subset pass count (0..17).
- T = 2 tasks. This is the smallest move W6.F1 names as resolvable at all.
- A pair of arms is **decisive** under a driver when |M(A) - M(B)| >= T.
- **FLIP** = a pair that is decisive under BOTH drivers with opposite sign, OR a different rank-1 arm under the two drivers.
- **Falsifier (the W6.B1 gate):** no FLIP means the sonnet driver does not change the ordering within band, so the
  sonnet arm is not needed per commit. Any FLIP means it stays in the per-commit plan.
- A pair that is decisive under one driver but below T under the other is reported, not counted as a FLIP.

## Self-test (can go red)

`python3 -I bench/agent-tasks/b1_driver.py --self-test`: identical driver tables -> SAME; a mutant where the sonnet
weakest arm passes everything and the strongest fails everything -> FLIP; chrome drift, a fallback judge row, a wrong
driver label and a missing row are each refused.

## Caveats (stated before the result)

- 3 runs per (driver, arm) on 17 tasks. The W6.F1 measurement put the per-run sd of a subset total near 1 task, so a
  2-task gap in M is about the resolution limit, not comfortably above it. A FLIP at T=2 is therefore weak evidence;
  a SAME is only as strong as the power of 3 runs.
- Per-run cost cap is `--max-budget-usd 1.00` (run_arm.py). A run that hits the cap counts as a fail; it is not
  retried. Cost is reported from the rows, not estimated.
- The `band` in the spec is a structural sanity band only (0..17). The verdict is the rule above.
