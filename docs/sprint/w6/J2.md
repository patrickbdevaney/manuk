# W6.J2 — event-sequence conformance (manuk vs Chrome Input.dispatch*)

chrome_ver=145.0.7632.116. Harness: `mcp/tests/event_sequences.rs` (`cargo test --release -p manuk-mcp --test event_sequences -- --nocapture`).
One page logs ~40 event types at window-capture (`w.`) and document-capture (`d.`); the same MCP action (click, click-input,
type, key Enter, key Tab, hover, focus) runs on a fresh session on each backend and the sequences are diffed.
Measured diff classes are pinned in `KNOWN`; a new class or a vanished one fails the test.
Vacuity: `MANUK_EVSEQ_MUTATE=drop-focus` removes focus/focusin from manuk's log -> test RED (NEW click-input/type missing focus, GONE focus-action extras).

## Diff classes (all real, none are CB.1.a.a: that focus gap is fixed)
1. **window-layer-silent** — every action: window capture listeners never see UA-dispatched events on manuk (document/body listeners do).
2. **(FIXED W6.J2.c) pointer events absent** — pointerover/enter/move never fire for click, hover (pointerdown/up do).
3. **(FIXED W6.J2.c) mouseover/mouseenter/mousemove before click missing**; hover fires mouseenter once where Chrome fires it down the ancestor chain (1 v 4, no enter on ancestors).
4. **focus order** — manuk fires focusin before focus (spec/Chrome: focus then focusin).
5. **type** — manuk synthesises keydown/keyup/select/change per char plus 2x beforeinput/input; Chrome `Input.insertText` gives 1x beforeinput+input, no key events, selectionchange around.
6. **key Enter / Tab** — manuk: no keypress, no beforeinput on Enter; Tab fires no blur/focusout/focus/focusin move (and keyup stays on the old target).
7. **(FIXED W6.J2.c) selectionchange** never fires on manuk.
8. Chrome-backend artifact: `act focus` on Chrome defers focus/focusin (page unfocused) and window `focus@win` appears; this makes enter/tab setup events spill into the compared slice.
