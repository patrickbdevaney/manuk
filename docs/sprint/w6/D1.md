## 2. The rule and its outcome

Rule (SYNTHESIS section 4, W6.B0/W6.D1 rows): if cdp-layer >= 40/102 task_pass_2of3 at HEAD, the RG gains were layer
gains, cdp-layer (Chrome) becomes the default backend for agents and for the GUI human view, and engine build work is
restricted to the security, fork and footprint lanes. Otherwise the engine stays the default.

**40 >= 40: the rule fires. Decision = Chrome default.** It fires at the boundary: one task fewer (39) and the
engine would have stayed default (the check's `--mutate -1` shows this). The rule was pre-registered as >= 40, so the
boundary result binds. The equal headline (40 vs 40) means the engine does not earn the default on reach; it does
not mean Chrome is ahead.

## 3. Backend default per lane

| lane | default backend | engine work allowed? |
|---|---|---|
| agents (manuk-mcp tool surface, REAL/held-out benches) | **Chrome (cdp-layer)** | no (layer work is backend-neutral and lands on Chrome first) |
| GUI human view (shell) | **Chrome** | no |
| security (untrusted-page reading, egress law, confinement, jitless) | engine available as the hardened backend; egress law must hold on both | **yes** |
| fork (fork-server, replay-to-fork, rollback/search) | engine | **yes** |
| footprint (PSS, pages/GB, cold start, concurrency) | engine | **yes** |
| conformance / render / JS-platform (WPT apertures, render fidelity, hover/event fixes on the engine) | n/a | **no**, except where a security/fork/footprint node needs it |

out of lane and set BLOCKED with this reason; W6.C1's engine half is out of lane (Chrome half only); the render
