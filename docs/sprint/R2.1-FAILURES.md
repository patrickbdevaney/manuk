# R2.1 — why manuk lost the R1.7 table (failure classes + token attribution)

Input: the 33 failing manuk rows (11 tasks failed in >=2 of 3 runs, plus L07 run 1) of SCOREBOARD.tsv, suite
`69903c…`, `chrome_ver=145.0.7632.116`. Output: `docs/sprint/FAILURES.tsv` (33/33 rows classified) from
`python3 -I scripts/r21-classify.py` (red: `--mutate drop-post` leaves 15 rows unclassified and agreement below 8/10).
Hand-labelled sample: `docs/sprint/r21/hand-labels.tsv`, 10 of 10 agree. Caveat: the labels were written by the same
agent that tied symptoms to causes, and SCOREBOARD stores only the first ~250 characters of each answer, no per-call
transcript, so symptom rules read answer text. Causes below were confirmed by driving `target/release/manuk-mcp`
against the fixtures (`docs/sprint/r21/probe.py`), not inferred from the answers.

| class | cause id | rows | tasks | root cause (reproduced) |
|---|---|---|---|---|
| act | agent-post-unsupported | 15 | F01-F05 | `agent/src/lib.rs` `submit_form` calls `forms::submission_url`, which returns `PostUnsupported` for every `method=post` form; the POST body builders (`urlencoded_submission_with_submitter`) are only used by `shell/src/gui.rs`. Every login, checkout and wizard step in the MCP fails with "form method=post is not implemented". |
| script | cssom-style-write-dead | 6 | F06, F10 | `el.style.display='block'`, `style.setProperty`, `style.color=` are silent no-ops in `manuk-mcp` and `a11y-dump` (`a.style.display` reads back `none`; `style.cssText=` and `setAttribute('style')` work). `install_supports_hook` in `engine/page/src/lib.rs:3497` installs `|_| false` without the `stylo` feature and `agent/Cargo.toml` enables only `spidermonkey`, so `CSS.supports` is false for everything and the validating setter rejects every value (`CSS.supports('display','none')` is false in both binaries). Dialogs and tabs toggled by inline style never open. |
| script | async-never-pumped | 6 | F07, F08 | `fetch()` started from a click handler (GET or POST) never reaches the server, and the `setInterval`/scroll-driven load of the feed stops after the first `/api/items` call (egress log shows one request). Reproduced with local pages and the fixture egress log. |
| script | document-write-head | 5 | L11, L12 | `document.write` from a `<head>` script is dropped on a minimal page and, on quotes.toscrape.com/js, the 10 quotes come out in reverse order (Steve Martin first, Einstein last; the page source order starts with Einstein). L12's 11th quote is wrong for the same reason. |
| target | model-miscount | 1 | L07 | The model counted Sharp Objects as the third book (Soumission is). Not an engine fault; no node. |

If all four engine causes are fixed, 11 tasks (F01-F08, F10, L11, L12) are recoverable; the gap to Playwright was
10 tasks on the >=2-of-3 measure. That is a bound, not a prediction.

## Token gap (manuk 964 vs Playwright 608 input+output tokens per row; 1.6x)

Per row, own suite, 3 runs each (SCOREBOARD):

| subset | arm | in+out tokens/row | cache_read/row | cache_create/row | turns/row |
|---|---|---|---|---|---|
| 11 tasks manuk failed | manuk | 1550 | 204,239 | 8,139 | 10.6 |
| same 11 tasks | playwright | 711 | 131,869 | 5,599 | 8.0 |
| other 29 tasks | manuk | 742 | 117,154 | 14,343 | 5.5 |
| other 29 tasks | playwright | 568 | 98,585 | 7,449 | 5.2 |

Per-call bytes (`docs/sprint/r21/bytes.py`, manuk observe vs the Playwright ARIA snapshot of the same page):

| page | manuk observe | manuk extract(text) | Playwright snapshot |
|---|---|---|---|
| books.toscrape.com | 6,742 | 2,246 | 16,662 |
| quotes.toscrape.com | 1,692 | 1,741 | 4,266 |
| en.wikipedia.org/wiki/Alan_Turing | 30,628 | 122,503 | 348,429 |
| fixture /shop, /login, /catalog, /product | 329, 215, 186, 223 | 187, 101, 226, 136 | 389, 116, 812, 118 |

Reading: on the three real pages manuk's observe is 2.5x to 11x smaller than Playwright's snapshot (on the tiny
fixtures /login and /product the Playwright snapshot is smaller), so observation size does not explain the gap.
Two things do: (1) the failing tasks cost 10.6 vs 8.0 turns and 2.2x the in+out tokens, because the model retries
refused actions; (2) cache_create per row on the passing tasks is 1.9x Playwright's (14.3k vs 7.4k) with only 5.1 KB
of manuk tool schemas, which the TSV cannot attribute (no transcript). Node R2.1.5 adds the transcript capture.
