# PERF.1 turnaround profile

chrome_ver=145.0.7632.116 · manuk commit f3a7c171 · 3-run bands are `median [min-max]` seconds. Generated by `scripts/perf1-profile.py`; raw rows in `docs/sprint/perf1/runs.jsonl`, manuk traces in `docs/sprint/perf1/traces/`, injection evidence in `docs/sprint/perf1/INJECT.txt`.

## Method

Both arms are reduced to the same nine phases and a wall time:
  dns, connect_tls, doc_fetch, subres_fetch, parse, cascade, layout, script, settle.

Attribution is EXCLUSIVE and by priority, so the phases of one load add up to its load time:
  manuk : every microsecond of [first request, navigate returned] goes to the highest-priority thing
          active in it: cascade > layout > dns > connect_tls > doc_fetch > subres_fetch; time that
          none of those covers falls to the engine's own load-phase it sits in (html parse -> parse;
          the script phases -> script; everything else -> settle); time no phase covers is
          `unattributed`. Plus startup (process spawn -> first request), a11y (tree build, a11y-dump
          only) and teardown, measured from independent clocks, so the whole sums to process wall.
  Chrome: cascade/layout/script are Performance.getMetrics RecalcStyleDuration/LayoutDuration/
          ScriptDuration; the network phases are the union-by-priority of the Network.* intervals,
          shrunk by the CPU fraction (assumes CPU and network overlap independently - a stated
          approximation, Chrome gives totals not intervals); parse = main-thread TaskDuration minus
          the three above; settle = what is left of navigation->load.

## Scope and caveats

- URLs where either engine never loaded (see the `OK n/3` lines) are excluded from the ranking; they are the reach problem (NET.REACH.1), not a phase.
- manuk's clock starts at the first request, Chrome's at the Document `requestWillBeSent`; Chrome's process wall (browser start included) is shown only for the R0.1 comparison.
- Chrome's cascade/layout/script are cumulative `Performance.getMetrics` totals and its network phases are shrunk by the CPU fraction (independence assumption), so a Chrome phase is accurate to the order of tens of ms, not a few. manuk's phases are exact interval attributions of one trace.
- manuk `settle` is the time inside `navigate()` after (and around) the engine's own `load event`: `finish_loading` phases, subframes, image/mask decode. Chrome's equivalent is ~0 because the CDP load event is the stop point; a Playwright `goto` also stops at the load event.
- Reproduce: `cargo build --release -p manuk-agent --bin a11y-dump && python3 -I scripts/perf1-profile.py --runs 3 --out docs/sprint/perf1` (needs `MANUK_CHROME_PIN`), `--self-test` for the instrument's own gate.

## PERF.1.3 results (chrome_ver=145.0.7632.116; manuk only, Chrome rows unchanged above)

Paired interleaved (`perf1-profile.py --manuk BASE --manuk-b NEW`, 20 URLs x 3 runs, raw rows `docs/sprint/perf1-pf13/paired.jsonl`);
BASE is HEAD df08661a built with the same command, NEW is HEAD + the font change below.

- **Cause of the fixed first-layout cost:** `FontContext::intern` copied a font file whole (`to_vec`) and `fallback_faces()` interned
  all nine fallback families the first time one character missed the primary face - colour emoji and a CJK collection are tens of MB
  each (CJK three times, one family name per collection face). example.com spent ~45 of its 50 ms there (strace: 368 font opens).
- **Fix:** fallbacks are looked up as ids and interned one at a time in list order (stop at the first face that covers); system
  font bytes are memory-mapped instead of copied (`FaceBytes`).
- **Result:** example.com layout median 50 -> 7 ms (bar <= 15 met; trace `layout` line, 3 runs). Every other URL within noise.
  Σ layout 10.29 -> 10.70 s (bar <= 5 **not met**): comix.to alone is 5.5-5.8 s.
- **Where the rest is (comix.to, `MANUK_LAYOUT_PROFILE=1`):** 6 cascade+layout passes of ~1.05 s each, 91% inside one taffy solve
  (123k measure probes, 6.2k distinct (node, width) misses, ~520 top-level item measures per pass). The top-level misses are
  dominated by `min_content_width` of three `<section>` items (layout of the whole subtree at width 1, 100-200 ms each, per pass).
- **Next fixed cost:** first use of each distinct face costs 8-12 ms (fontdue parses every outline eagerly): quotes.toscrape.com/js first
  layout 28 ms (Liberation Serif, Serif Bold, Sans Italic) before and after this change.
- **Not comparable:** the pre-sprint `target/release/a11y-dump` that sat in the tree (Alan_Turing cascade 106 ms, wall 4.7 s) is ~2.4x
  faster in cascade than a clean build of HEAD (250 ms, wall 7.8 s) - see PERF.1.3.c.

## PERF.1.4 results (script phase)

chrome_ver=145.0.7632.116. Paired same-minute A/B on example.com, 7 runs, `scripts/perf1-profile.py --manuk-b` with arm B =
`MANUK_NO_PREWARM=1` (same binary); rows in `docs/sprint/perf1-pf14/paired.jsonl`.

- **Profile of the fixed cost** (example.com, `Instant` timers, release): `Runtime::new` 9.1 ms; `install` (native DOM/BOM bindings) 9.7 ms;
  `event_loop::install` 14 ms of which the 487 KB `event_loop_prelude.js` alone is 8 ms of compile+run and the other 14 preludes 6 ms;
  `JSEngine::init` + the helper-thread spawns are in the 9 ms. Total `load_document` 33 ms before this change.
- **Fix:** `Agent::load_url` builds the thread's JS runtime (`manuk_js::prewarm`) *after* issuing the document request, so engine +
  context creation overlaps DNS/TLS/transfer. The teardown guard is armed afterwards (`prewarm_settle`, on every exit path), because it
  must register after the page's thread-locals (arming it inside prewarm segfaults at exit - measured). `g_prewarm_exit` covers script,
  script-free and (mutant) unsettled children.
- **Result:** example.com script phase median 51.1 -> 41.5 ms (7 paired runs, bands 50.7-53.7 vs 41.4-41.7). Bar <= 15 ms **not met**.
- **Not measured:** Σ script over the 20 URLs (bar <= 5 s from 9.48): the change saves ~10 ms per page, so the long pages are untouched.
- **Where the rest is:** ~26 ms is the per-document global (`install` 10 + event-loop preludes 14 + script) and ~15 ms of the 41 is the
  initial cascade+layout inside `from_dom`, which the trace does not emit as `cascade`/`layout` lines and so lands in `script`.
